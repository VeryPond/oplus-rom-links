# 区域拆分口径

本文说明为什么把「机型 × 地区」拆成独立条目，以及地区码表。

---

## 1. 为什么拆

同一个机型在不同地区是**不同的固件、不同的 model 代码、不同的版本号**：

```
OnePlus 15
  CN   PLK110_17.0.1.201(CN01)   8.93 GB
  EU   CPH2747_17.0.0.102(EX01)  8.31 GB
  GLO  CPH2747_17.0.1.201(EX01)  8.37 GB
  IN   CPH2745_17.0.1.201(EX01)  8.66 GB
  NA   CPH2749_16.0.3.503(EX01)  8.75 GB
```

如果按机型合并成一行，用户根本不知道自己要下哪个。
所以站点的数据结构是 `(机型, 地区)` 二元组。

## 5. 目录源 vs 官方源

两个源的地区标注**不一致**，这是外部数据问题：

| 源 | 地区写法 |
|---|---|
| 第三方目录 | `CN` / `EU` / `GLO` / `IN` / `TW` / `EEA` |
| 官方接口扫描 | `cn` / `eu` / `in` / `sg` / `ru` / `tr` / `th` / `gl` / `id` / `tw` / `my` / `vn` / `ph` |

注意 `GLO`（目录）和 `gl`（官方）是同一个东西，`EEA` 和 `eu` 有重叠但不完全等价。
合并时统一转大写，不强行归一 —— 因为改动会丢失原始信息。

---

## 6. 已知缺口

1. **冷门地区未穷举**：每型号只试 4~10 个主要地区，`sa`/`mea`/`roe`/`la`
   这些没扫，可能有版本漏掉。
2. **同一机型的不同地区 model 代码未必都知道**：比如 Find X9 国行是 PLJ110、
   海外是 CPH2797，但如果某个地区用了第三个代码而我不知道，就会漏。
